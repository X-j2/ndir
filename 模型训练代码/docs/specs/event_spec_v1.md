## 1. 目的

定义可复现的参考轨道事件时间线，用于：

- U2 窗口标签（`labels_spec_v1.md`）；
- 事件级评价（TTD、FA/h、事件召回/PPV/F1）；
- 上位机事件引擎的真值输入（回放/评估）。

本规范只定义**参考轨道事件**，不定义设备实时检测算法。

## 2. 主事件：U2（参考 EtCO₂ 低值/CO₂ 缺失样事件）

### 2.1 定义

```
轨道: etco2
采样: 100 Hz
网格: 1 s
缺失: NaN 或 <=0
前向填充上限: 10 s；超过上限记 unknown
阈值: etco2 < 10
合并: 同类事件间隔 <=10 s
最短持续: 10 s
顺序: 先合并，后丢弃短段
```

### 2.2 计算步骤（必须按顺序）

1. 对 100Hz `etco2` 做前向填充：
   - `NaN` 或 `<=0` 视为缺失；
   - 每个有效值最多向后保持 10s；超过 10s 变为 NaN（unknown）。
2. 按 1s 网格取样：取每个整数秒处的填充值（`filled[::100]`）。
3. 生成布尔掩码 `etco2_1s < 10`。
4. 找到所有连续的 True 段（半开区间 `[start, end)`，单位秒）。
5. **先合并**：若相邻两段之间的 False 间隔 `<=10s`，**且该间隔内没有 unknown**，合并为一段。
   - unknown = 前向填充超过 cap 后的 NaN；
   - 间隔内只要有一个 unknown，就**不得合并**；
   - 这条规则对 U2（cap=10，merge=10）和 RR<3（cap=10，merge=20）都适用。
6. **后丢弃**：合并后的段若 `end - start < 10s`，丢弃。
7. 输出事件：`{case_id, class="U2", start_s, end_s, duration_s}`。

**为什么先合并后丢弃**：两个 6s 的低值段被 5s 正常段隔开时，合并后是 17s 事件；若先丢弃短段，两个 6s 段都会被删。规范冻结此顺序，但合并必须满足“间隔全部可观测”。

**为什么不能跨 unknown 合并**：参考轨道在长缺口后是 unknown，不是“正常”。把两个低值段跨 unknown 合并会把“未知”当成“呼吸正常”，制造更长的假事件；RR<3 的 cap=10/merge=20 尤其会触发。Stage 0 的 rev1 已改为不跨 unknown，旧的 428/189、93/72 不再作为冻结值。

### 2.4 实际读数支撑与低可信处理（rev3 修正）

**定义**：“实际 EtCO₂<10 读数” = 原始 100Hz 参考轨道中一段连续有效、且 `<10` 的样点；不是 1s 网格值，也不是每个 100Hz 样点。

**冻结的支撑关联边界规则（rev3）**：

1. 对事件内每个 1s 低值网格点 `g`，找到它前向填充的来源样点 `src(g)`（最近一个有效原始样点）。
2. 若 `src(g)` 位于某个原始低值读数运行段 `R` 内，则 `R` 支撑该事件。
3. 事件的实际读数 = 所有支撑该事件网格点的**不同原始读数运行段**数；同一运行段支撑多个网格点只计 1。
4. `src(g)` **可以早于事件整数秒起点**，只要该网格点仍处于 cap 有效期内且被填充为低值。支撑计数不得简单切片 `track[start_s*100:end_s*100]`。
5. 未被任何事件网格点取为 ffill 来源的原始低值样点，不计入该事件。

这条规则消除了“网格事件从 1s 开始、触发读数在 0.5s，却被计为 0 读”的错位。示例：0.5s 单读 → 事件 `[1,11)`、支撑 1（低支撑）；0.5s + 10.5s 双读 → 事件 `[1,21)`、支撑 2（可靠）。

- **可靠事件**：关联读数 **≥2**。
- **低支撑事件**：关联读数 **<2**（本次复算均为 1 读；0 读为 0）。
- 低支撑事件**不得**计入可靠正例，也**不得**改作负例；窗口标签映射为 `ignore_low_support`，训练/主指标排除；事件级评价单独报告，不进入主 TP/FN。

| cap | 事件总数 | 病例 | 可靠(≥2读) | 可靠病例 | 低支撑(<2读) | 低支撑病例 | 0读 | 0读病例 | 1读 | 1读病例 |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 5s | 55 | 16 | 55 | 16 | 0 | 0 | 0 | 0 | 0 | 0 |
| **10s（规范）** | **451** | **189** | **376** | **178** | **75** | **59** | **0** | **0** | **75** | **59** |
| 20s | 428 | 189 | 371 | 179 | 57 | 49 | 0 | 0 | 57 | 49 |

**判读：**

- cap=10 的 451 个事件中 **376 个（83.4%）** 有 ≥2 条关联读数支撑；**75 个（16.6%）** 是低支撑，且全部是单读。rev2 的 277/174 与 73 个“0 读”是切片计数错位造成的，已作废。
- cap=5 的 55 个事件全部有 ≥2 条关联读数；但 cap=5 仍有 3,097 次 unknown 阻止合并，不能因此认为 cap=5 更适合主口径。
- cap=20 的可靠数为 371/179，低支撑 57/49；与 cap=10 接近，但事件定义更长，仍以 cap=10 为主口径。
- **冻结划分只用可靠事件**；低支撑事件不参与 U2 正例和事件分层，但会作为 `ignore_low_support` 窗保留在数据中，不能被静默当成负例。

## 5. 事件字段与文件格式

每个事件至少包含：

```json
{
  "case_id": 12,
  "class": "U2",
  "start_s": 135,
  "end_s": 159,
  "duration_s": 24,
  "track": "etco2",
  "cap_sec": 10,
  "merge_gap_sec": 10,
  "min_duration_sec": 10,
  "spec_version": "event_spec_v1"
}
```

- 时间单位：秒，相对病例起始；
- 半开区间 `[start_s, end_s)`；
- 事件时间线按病例独立；
- unknown 区间单独保存（`unknown_intervals`），不得桥接事件。

## 6. 监测小时与可评估时间

事件级指标的分母必须写明：

- `total_hours`：病例总时长（有任意数据）。
- `evaluable_hours`：参考轨道可用且未被 UNKNOWN/长缺口排除的时间。
- **主 FA/h 使用 `evaluable_hours`**；同时报告 `total_hours` 作为敏感性。
- UNKNOWN 区间内的告警不参与 TP/FP，单独报告 `unknown_alarm_rate`。
- 无参考时段、断线、饱和、长缺口都不得默认成“正常”。

## 8. 验收测试

1. `etco2=5` 持续 30s → 1 个 U2 事件（注意：`etco2=0` 被视为缺失，不能直接构成事件）。
2. `etco2=5` 持续 6s + 正常 5s + `etco2=5` 持续 6s → 合并后 17s，保留 1 个事件（先合并后丢弃）。
3. `etco2=5` 持续 6s，单独 → 丢弃。
4. 10s 缺口 → ffill 到 10s；11s 缺口 → 超过上限，事件断开。
5. 事件时间线不跨病例。
6. 同一输入重复运行，事件数/起止完全一致。
7. **最小 unknown 合并反例**：两个低值段间隔 `<=10s`，但间隔含 unknown → 不合并；若两段各自 `<10s`，应全部丢弃（0 事件），不能合成 1 个事件。
8. **RR<3 版本**：cap=10、merge=20，两个 12s 低值段中间 15s 缺口（含 5s unknown）→ 2 个事件，不是 1 个。
9. 250 例复算得到 U2 总事件 **451/189**，其中可靠（≥2读）**376/178**、低支撑（<2读）**75/59**（均为 1 读）；RR<3 **98/72**（rev3）。
10. 单次读数事件 → `low_support`；只与它重叠 ≥50% 的窗 → `ignore_low_support`，不是 U2，也不是负例。
11. 冻结划分的 U2 正例只用可靠事件；低支撑事件单独计数，不进入分层。
12. 旧类 2 窗段 536/169/132（过滤）和 627/209/149（未过滤）不变。
13. **0.5s 单读**（其余 NaN，cap=10）→ 事件 `[1,11)`，关联读数 1，低支撑。
14. **0.5s + 10.5s 双读** → 事件 `[1,21)`，关联读数 2，可靠。
15. **真实病例回归**：VitalDB case 1 的 ETCO2 `[355,380)` 段，事件 `[5,23)` 关联 3 条读数；第一条在 4.03s（事件起点前），只切片会误计为 2。测试夹具 `tests/fixtures/case1_etco2_355_380.json`。
16. `iter_windows()` 不传事件表时必须自行构建并拆分可靠/低支撑；低支撑事件不得因默认路径被当成 U2。

## 9. 已知限制

- EtCO₂<10 是设备参考值，不代表临床呼吸暂停；可能来自漏气、脱管、采样管故障、低幅信号。
- 前向填充上限、合并间隔、以及“不跨 unknown 合并”对事件数有可见影响；论文必须报告敏感性。cap=5 的 55/16 不是“更好”，而是 unknown 阻断合并的后果。
- 参考轨道密度低；事件起止精度约 1–2s，不能宣称毫秒级。
- unknown 区间不能当正常，也不能当事件；事件引擎/评价必须单独报告 unknown 覆盖率。
- 事件时间线只用于评估/标签；设备实时检测必须另行定义 UNKNOWN/SUSPECT/ACTIVE，见 `event_matching_spec_v1.md` 与 `quality_abstention_spec_v1.md`。
