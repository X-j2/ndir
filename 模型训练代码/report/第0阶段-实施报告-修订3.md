## A. 本阶段完成项及修改文件

### A.1 三项修订

1. **事件支撑改为“原始读数 ↔ 事件网格”的实际关联计数**
   - `tools/stage0_common.py` 新增：
     - `ffill_source_indices()`：为每个 100Hz 样点找到其前向填充来源；
     - `_support_from_context()`：按事件内每个低值 1s 网格点的 ffill 来源，统计不同原始读数运行段；
     - `count_actual_readings()` 现在接受 `cap_sec`，并按同一规则计数。
   - **冻结边界规则**：
     1. 事件网格点 `g` 的低值来自最近一个有效原始样点 `src(g)`；
     2. 若 `src(g)` 属于某段连续低值原始读数，则该读数支撑事件；
     3. 同一原始读数段支撑多个网格点只计 1；
     4. `src(g)` 可以早于事件整数秒起点，只要 `g` 仍在 cap 有效期内且被填充为低值；
     5. 未被任何事件网格点取为 ffill 来源的低值原始样点，不计入该事件。
   - 这修复了 0.5s 触发读数导致的“事件从 1s 开始、却被计为 0 读”的错位。
   - `build_events()` 在整条轨道上一次性计算低值/有效运行段 ID，避免逐事件重复扫描。

2. **修复 `iter_windows()` 默认路径绕过低支撑划分**
   - 旧行为：`u2_events=None` 时把所有 U2 事件（含低支撑）当作可靠；`low_support_events` 默认 `[]`。
   - 新行为：
     - 任一事件表为 `None` → 重新构建 U2 事件并拆分可靠/低支撑；
     - 只补缺失的一侧；显式传 `[]` 才表示“不做低支撑处理”。
   - 新增测试：连续低值参考只有 1 条原始读数时，默认 `iter_windows()` 标签必须是 `ignore_low_support`，不能是 U2。

3. **重算、规范、测试、hash、报告**
   - 重新生成 `data_splits/*`、`stats.json/md`、`quality_analysis.json/md`。
   - 更新四份规范与 SSOT。
   - 新增 0.5s 单读、0.5s/10.5s 双读、真实病例回归、默认 `iter_windows` 测试。
   - 重跑 43 项边界测试与 115 项上位机回归。

## D. 数据统计口径、结果文件和 hash

### D.1 修订后的定义

- U2 事件：`etco2<10`，1s 网格，ffill cap 10s，合并间隔 ≤10s 且间隔无 unknown，最短 10s；先合并后丢弃。
- **实际读数支撑**：原始 100Hz 轨道中连续有效、`<10` 的读数运行段；某段只要是一个事件内低值网格点的 ffill 来源，就支撑该事件。来源可早于事件整数秒起点，但网格点必须在 cap 内且为低值。
- 可靠 = 关联读数 ≥2；低支撑 = <2。低支撑不判正/负，窗口映射 `ignore_low_support`。
- 窗口标签：可靠重叠 ≥50% → U2；低支撑重叠 ≥50% → `ignore_low_support`；可靠边界 10–50% → ignore；低支撑边界 10–50% → `ignore_low_support`；其余按 RR 中位数。
- 质量历史：15s bin、15s 步长；只用 `bin.end_s <= window.start_s`。
- ACTIVE/SUSPECT 规则不变（rev2 已冻结）。

## F. 尚未解决的风险

1. U2 语义仍是“参考 EtCO₂ 低值/缺失样事件”，不是临床确诊屏息。
2. 低支撑事件（75/59）仍全部是单读；它们可能是真事件或 ffill 伪迹，当前无法区分，只能 `ignore_low_support` 单列。
3. cap=5 的 55 个事件全部可靠，但伴随 3,097 次 unknown 阻止合并；不能把“事件少但都可靠”当成更优口径。
4. VitalDB 术中机械通气 vs 样机自主呼吸的域偏移未解决。
5. 设备数据不可用；无实时验证；固件无标定 flag/帧序号，实时 C 模式禁用。
6. 质量阈值（A_floor=1.0、300s 近史、15s bin、30s 最短历史）仍暂定；Stage 1 只能在开发集冻结。
7. `FLAT_EVER_HISTORY` 是长屏息/低置信候选，也可能是拔管/断线；不能单独报警。
8. Final Test 可靠 U2 73/35 仍偏少；事件级 CI 会宽，不能报单点精度。
9. ACTIVE 有效重叠阈值（1s/5%）会减少“短促擦边”TP；这是有意预冻结，Stage 3/4 必须报告 early/late 比例。
10. 未训练 U15/U30、未做校准/融合、未做上位机接管；旧固件四分类仍会驱动旧告警。
