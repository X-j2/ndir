## A. 本阶段完成项及修改文件

### A.1 五项修复

1. **事件合并不得跨 unknown**
   - `tools/stage0_common.py` 新增 `merge_intervals_no_unknown`：只有 `gap <= merge_gap` **且 gap 内无 unknown** 才合并。
   - `build_events` 返回 `merge_blocked_by_unknown` 计数。
   - 新增最小反例测试：两个低值段间隔 <=10s 但间隔含 unknown，不得合并；若两段各自 <10s，应全部丢弃，不能合成一个事件。
   - 因事件规则变化，重新生成 `data_splits/*`、重算所有尺度标签、事件数、Final Test 和统计；**428/189、93/72 不再是冻结值**。

2. **质量状态改为因果历史，删除对完整病例未来数据的依赖**
   - 新增 `tools/quality_state.py`：`breathing_bins` + `history_from_bins`，只使用 `bin.end_s <= window.start_s` 的 bin；未来 bin 永远不参与。
   - 质量状态拆为：
     - `FLAT_WITH_HISTORY`：近 300s 有已验证呼吸（高置信候选）；
     - `FLAT_EVER_HISTORY`：近 300s 无、但更早已有（长屏息/低置信候选，不能单独报警）；
     - `FLAT_NO_HISTORY`：过去从未有已验证呼吸（UNKNOWN）；
     - `FLAT_HISTORY_UNKNOWN`：历史不足 30s（UNKNOWN）。
   - 删除 `case_has_breathing` 与“完整病例其他时段有呼吸”的判断。
   - 新增测试：未来呼吸不改变当前窗状态；未来 bin 不被计入历史。

3. **事件匹配修订**
   - `tools/event_matching.py`：
     - 正确计算 `IoU = intersection / union`（不是 intersection / max duration）；
     - **ACTIVE TP 必须有时间重叠 >0**；无重叠的宽限时间只作 `early_alarm`/`late_alarm` 诊断，不计 TP；
     - 一对一匹配；重复告警 1 TP + 1 FP；
     - SUSPECT 单独 `match_suspect`：严格早于 onset，`0 < lead <= 10s`；不进入 ACTIVE TP/PPV/F1/FA/h。
   - 新增 9 项最小反例测试。

4. **修复 `split_manifest.json` 自引用 hash**
   - 清单只记录 `hash_targets` 中 4 个数据文件的 SHA256；不再把 `split_manifest.json` 自己的 hash 写进自己。
   - 新增 `data_splits/split_manifest.sha256` 侧车，记录清单自身的 hash。
   - 新增测试：`hash_targets` 与 `hashes` 键完全一致；每个 hash 重算一致；清单不含自身；侧车能校验清单；test/dev 不重叠。

5. **边界测试、复算与回归**
   - 新增 `tests/` 33 项 `unittest` 边界测试，全部通过。
   - 重跑 `build_frozen_splits.py`、`recompute_stage0_stats.py`、`analyze_flat_quality.py`。
   - 重跑上位机 7 个测试文件、115 项，全部通过。

## D. 数据统计口径、结果文件和 hash

### D.1 修订后的定义

- U2 事件：`etco2<10`，1s 网格，ffill cap 10s，**合并间隔 ≤10s 且间隔无 unknown**，最短 10s；先合并后丢弃。
- RR<3 敏感性：`rr<3`，1s 网格，cap 10s，**合并间隔 ≤20s 且间隔无 unknown**，最短 10s。
- U2 窗：事件重叠 ≥50%；10–50% ignore；其余按 RR 中位数。
- 质量历史：15s bin、15s 步长；只用 `bin.end_s <= window.start_s`；近 300s 为 `FLAT_WITH_HISTORY`，更早为 `FLAT_EVER_HISTORY`，从未为 `FLAT_NO_HISTORY`。
- ACTIVE 匹配：必须有时间重叠；无重叠宽限只作诊断；SUSPECT 单独。

## F. 尚未解决的风险

1. U2 语义仍是“参考 EtCO₂ 低值/缺失样事件”，不是临床确诊屏息。
2. VitalDB 术中机械通气 vs 样机自主呼吸的域偏移未解决。
3. 设备数据不可用；无实时验证。
4. 固件无标定 flag/帧序号；实时 C 模式仍禁用；实时链路丢帧不可检测。
5. 质量阈值（A_floor=1.0 mmHg、300s 近史、15s bin、30s 最短历史）仍是暂定；Stage 1 只能在开发集冻结。
6. `FLAT_EVER_HISTORY` 可能是长屏息，也可能是“曾经有呼吸、随后拔管/断线”；需要 Stage 1 的基线连续性/断线判别，当前不能单独报警。
7. 事件数仍偏少（Final Test U2 88/38；RR<3 17/14），CI 会宽。
8. ACTIVE 严格重叠规则会减少“晚到但落在 30s 宽限”的 TP；这是有意的，但 Stage 3/4 必须报告 late_alarm 比例，不能偷偷放宽。
9. 未训练 U15/U30、未做校准/融合、未做上位机接管；旧固件四分类仍会驱动旧告警。
10. 旧 0.910/0.888 只属于旧 4 类模型，不得用于新 U 模型或未标定设备。
